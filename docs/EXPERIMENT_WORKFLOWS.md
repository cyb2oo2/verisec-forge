# Experiment Workflows

This document describes the retained workflows after pruning. Historical baseline/SFT/DPO config matrices were removed from the application-facing repository; the remaining workflows support the paired-diff research story, reproducibility checks, and the patch-review demo.

## 1. Verify The Repository

Run the focused test suite:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

The tests cover core parsing/evaluation utilities, serving behavior, report-index generation, reproducibility helpers, and retained report scripts.

## 2. Validate Manifest-Backed Artifacts

Use check-only mode when you want to confirm that local materialized inputs match the recorded hashes without regenerating reports:

```powershell
.\.venv\Scripts\python.exe scripts\reproduce_primevul_calibrated_router.py --check-only
.\.venv\Scripts\python.exe scripts\reproduce_primevul_evidence_coupled.py --check-only
.\.venv\Scripts\python.exe scripts\build_reproducibility_bundle.py --manifest reproducibility\external_generalization_manifest.json --check-only --include-generated
```

These checks are the fastest way to prove that the local machine has the same data/prediction artifacts used by the retained reports.

## 3. Regenerate Main Reports

The headline tables and charts are generated by small scripts:

```powershell
.\.venv\Scripts\python.exe scripts\build_primevul_progressive_controls.py
.\.venv\Scripts\python.exe scripts\build_primevul_progressive_controls_chart.py
.\.venv\Scripts\python.exe scripts\build_primevul_main_results.py
.\.venv\Scripts\python.exe scripts\build_primevul_main_results_chart.py
.\.venv\Scripts\python.exe scripts\build_final_submission_statistics.py
```

Pair-coupled and router evidence is generated through the corresponding retained scripts under `scripts/`.

## 4. Rebuild The Results Index

The curated index is driven by `configs/report_index.json`:

```powershell
.\.venv\Scripts\python.exe scripts\build_report_index.py --manifest configs\report_index.json --output-path reports\RESULTS_INDEX.md
```

Only retained application-facing artifacts should be added to this config.

## 5. Run The Patch-Review Demo

Start the local server:

```powershell
.\.venv\Scripts\python.exe -m vrf.cli serve --config configs\serve_patch_review_demo.json
```

Then open:

```text
http://127.0.0.1:8000/review-pair/ui
```

The demo is artifact-backed. It is for inspecting reproduced paired examples and evidence traces, not for arbitrary online vulnerability scanning.

## 6. Add A New Experiment

Use this gate before adding anything:

1. Does it strengthen the paired-diff, source-routing, or evidence-coupled audit story?
2. Does it have a clear negative control or stress condition?
3. Can it be summarized by one retained report rather than a directory of intermediate sweeps?
4. Can local inputs be listed in a manifest if they are too large to commit?
5. Does it need a focused test?

If the answer is no, keep it outside the application-facing repository.
