# VeriPatch-RR Semantics-Free Structural Control

Generated by `scripts/evaluate_veripatch_rr_structural_control.py`.
Artifact: `reports/veripatch_rr_structural_control_v1.json`.

Standing Rule 8 (`docs/RESEARCH_INTEGRITY_REMEDIATION.md`) requires every claim
of model signal to be measured against the **strongest** semantics-free control.
That rule ended the PrimeVul detector arc but was never applied to the relational
arc: `char_polarity` appeared in exactly one report and never entered
VeriPatch-RR, the readout arc, or the repair arc. This report closes that gap.

Reproduce:

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_veripatch_rr_structural_control.py
```

## The control

`char_polarity`: net added-minus-removed **character** count of the rendered
diff. It reads only line-leading `+`/`-` markers (excluding `+++`/`---` file
headers) and never the content of any line. Sign and threshold are fit on the
6,000-row side-choice **training** split only and applied unchanged.

| Property | Value |
| --- | ---: |
| fitted sign / threshold | `+1` / `0.0` (the predetermined split) |
| training balanced accuracy | `0.8351` |
| training pairs ∩ audit pairs | **0** |
| tie rate, mixed audit / CrossVul audit | `0.0300` / `0.0229` |

Ties are broken by a seeded coin flip. Metric definitions are imported from
`src/vrf/cross_model_relational_analysis.py::_swap_diagnostics`, and inference is
pair-clustered per Standing Rule 5.

Systems compared: the frozen baseline classifier (`model`) and the repaired
model under antisymmetric inference (`repaired_antisym`) — the paper's strongest
system, from `reports/REPAIR_ANTISYMMETRIC_RESULT_V1.md`.

CrossVul (350 pairs, unseen source) agrees: `repaired_antisym − control` is
`-0.0086` on canonical accuracy (`p=0.728`) and `+0.0029` on

**On PrimeVul the repaired system and the control are exactly tied on
both-directions-correct (`0.8400` vs `0.8400`).** On PatchEval and CrossVul the
difference is within noise. The fine-tuned baseline is significantly *behind* the
control everywhere. The entire measured advantage of the antisymmetric repair
comes from DeltaSecommits — and that source is corrupted.

## The DeltaSecommits advantage is a data-ingestion defect

**Correction to an earlier version of this report.** The broken side-swap
mirrors were previously attributed to `difflib.SequenceMatcher` being an
asymmetric algorithm. That was wrong. Recomputing opcodes directly on the source
code, with and without `autojunk`, `char_net` is **exactly antisymmetric on
100%** of pairs tested. `difflib`'s matching is not the problem.

The real cause is upstream. Some sources store an entire function on a single
line with no trailing newline:

| Source | single-line `code` records | broken swap mirrors in audit |
| --- | ---: | ---: |
| PrimeVul | 0% (0/400) | 0 / 200 |
| PatchEval | 1.75% (7/400) | 25 / 200 |
| DeltaSecommits | **100% (400/400)** | **200 / 200** |

With a one-element line list and no trailing newline, `difflib.unified_diff`
emits the added body on the *same physical line* as the removed body:

```
@@ -1 +1 @@
-static int elo_probe(...) 	usb_put_dev(udev); 	kfree(priv); 	return ret; }+static int elo_probe(...) 	kfree(priv); 	return ret; }
```

There is no line-level `+`/`-` structure at all — one run-on line holds both
sides. The control reads it as a single giant removed line, which is why its
both-directions-correct on DeltaSecommits is `0.0000`: it cannot flip, because
nothing in the rendering flips.

Consequences:

1. **One third of the representative suite is malformed.** Every side-swap,
   equivariance, and both-directions-correct number computed over the mixed
   suite is contaminated, independently of this control.
2. The mixed-suite exact-mirror rate is `0.6250`; CrossVul (whose records retain
   newlines) is `0.9857`. The gap is entirely explained by source ingestion.
3. The repair's headline win is measured on rows whose input is corrupt.

The fix is at ingestion — restore newlines in the DeltaSecommits and PatchEval
pair builders, or exclude single-line records — not at the diff renderer.

## `split_view`: the information survives, the model does not

Across the five held-out nuisance families the control wins four:

| Family | control | model | delta | control coverage |
| --- | ---: | ---: | ---: | ---: |
| `diff_algorithm_myers_header` | **0.8433** | 0.6367 | `-0.2067` | 0.950 |
| `diff_algorithm_histogram` | **0.8417** | 0.6467 | `-0.1950` | 0.950 |
| `context_window` | **0.7183** | 0.6217 | `-0.0967` | 0.970 |
| `whitespace_comment` | **0.7150** | 0.6383 | `-0.0767` | 0.970 |
| `split_view` | *no coverage* | 0.5133 | — | **0.000** |

`split_view` regroups identical content into `Removed from Side A` / `Added in
Side B` / `Unchanged context` blocks with no `+`/`-` glyphs, so `char_net == 0`
on 100% of rows and the glyph-reading control has zero coverage.

But the polarity **information is still there**, stated in English. A *prose*
control that parses the block headers and applies the identical net-character
rule recovers it:

| Variant | prose control | model |
| --- | ---: | ---: |
| `canonical__split_view` | **0.8433** | 0.5133 |
| `side_swap__split_view` | **0.8417** | 0.4850 |

The prose control scores **higher** under `split_view` (`0.8433`) than the glyph
control does on the canonical unified diff (`0.7217`) — the transformation makes
the signal *more* extractable, not less. The model is at chance on the same rows.

So the correct statement is **not** that removing polarity ablates the model's
signal. Polarity is fully present and more recoverable than before. The model
cannot read it once it is written in words instead of `+`/`-` glyphs.

This converges with `reports/QWEN_LABEL_ONLY_SWAP_VS_STRUCTURAL_SWAP.md`, where
swapping the prose side labels left the prediction almost unchanged
(`phi = +0.914`). Two independent interventions, one conclusion: this classifier
does not read natural-language statements of the patch relation.

It also identifies the functional form `reports/POLARITY_GOLD_CONFOUND.md` left
open ("polarity sensitivity is real but its functional form is unidentified",
~56% row agreement), and explains the `0.925` `split_view` violation rate that
`reports/REPAIR_ANTISYMMETRIC_RESULT_V1.md` parked as future work: there is no
content-based fallback to degrade to.

## Verdict

1. No system in this repository outperforms a semantics-free character-counting
   rule on VeriPatch-RR on any well-formed source.
2. On PrimeVul the repaired antisymmetric system ties the control exactly on
   both-directions-correct (`0.8400` vs `0.8400`); on PatchEval and CrossVul the
   difference is within noise.
3. The repair's only measured advantage is on DeltaSecommits, where 100% of rows
   are malformed by a source newline defect.
4. That defect contaminates every side-swap number computed over the mixed
   representative suite and must be fixed at ingestion.
5. The classifier's competence is bound to the `+`/`-` glyph channel: the same
   relation in prose is recoverable at `0.8433` by a character rule and unusable
   by the model.

## Claim boundary

One control rule, one fitted threshold, four sources, one frozen baseline
checkpoint and one repaired checkpoint at length 1024. This does not establish
that no learned model can exceed diff-shape structure — it establishes that none
of the systems currently in this repository does, on these populations. The
`split_view` and prose-control results are single-family interventions on one
checkpoint and are correlational with respect to internal mechanism.
