**3. 反对称保证、极性不变和安全语义是三件事**

`src/vrf/antisymmetric_pair_head.py` 已准确指出：反对称本身不保证 polarity invariance。但训练脚本和结果报告仍有“两个性质都 exact by construction”的表述。

对于 `s(x)=g(x)-g(Sx)`，若 S 是严格的交换 involution，则 `s(Sx)=-s(x)`。这不能推出另一个极性变换 P 下 `s(Px)=s(x)`。要得到后者，需要明确的输入规范化或对正确变换群做投影，并验证推理实际运行了该路径。

当前 `antisymmetric_inference_correctness` 只读取 canonical / side_swap 的分数来计算正确率，不读取 polarity-only 分数。因此它本身不能验证报告带星号的 polarity-only accuracy。若历史派生文件将同一 canonical 决策传播到其它 rendering，应该将其描述为使用已知变换映射的结构化解码，而不是模型对任意新输入都学会了极性不变。

另一个真实边界是平局：当前 `score > 0` 选 B，否则选 A。在 `score=0` 时，原顺序和交换顺序都选 A；本次反例重现了概率反对称成立、离散标签交换失败。应给出 abstain/tie 合约及平局频率，而不是无条件声明二元决策永远精确等变。这里没有证明历史预测实际出现了平局。

即便上述性质全部成立，始终选择代码更短的候选也可以在换名和换方向时保持一致，却未必理解漏洞。这是当前 benchmark 的核心外推限制：一致性是必要条件，远非语义理解的充分条件。

**4. “独立性”“极性机制”“训练中介”需要更窄的推断**

`QWEN_SIDE_SWAP_POSITIONAL_INDEPENDENCE.md` 报告 phi=-0.024、p=0.559，并称建立了统计独立和 content-blindness。该检验只是在当前样本中没有拒绝边际独立，并没有证明模型丢弃了代码内容。相同设置下 side-swap accuracy 约 0.665，本身也提示不能简单地说交换后完全没有与答案相关的信号。来源混合可能进一步掩盖条件相关性。

建议改为：“在该审计集的总体二元输出层面，canonical 与 swapped 的关联较弱，未发现显著偏离边际独立。”如要主张“近似独立”，预先给出可接受相关性区间并做等效性分析；同时报告来源/长度分层、概率层面关系，以及正确性耦合。不要从输出相关系数直接推断隐藏状态缺少语义。

label-only 变换的 gold 是翻转的：标签不变是失败，不是稳健性成功。它支持“模型没有正确追踪候选名称与内容的映射”。polarity-only 是重新生成 reverse diff 后恢复候选命名，会联动 `+/-`、内容出现顺序、方向文字、hunk 组织和 token 位置。它支持对“方向/呈现结构干预”的行为敏感性，还没有孤立到单一符号通道或某个注意力机制。

“净增删行数能预测标签”同样需要区分：依赖 rendering 方向、不能映射回候选身份的策略违反任务；利用真实代码长度或新增检查的先验可能只是语义不足的内容启发式。不能仅凭相关性宣布所有改动量信息都非法。

读出线是目前更扎实的证据链：独立的 180 对、未见 suffix 和两个训练种子确认了后缀稳定性差异；固定一个 backbone 的匹配头比较进一步支持 changed-hunk 的直接结构效应。但 canonical 非劣未建立，固定 backbone 的两个种子只改变线性头。mean 的 direct effect 不显著，也不等同于严格证明其全部收益由训练中介。

对于因果 decoder，位于 suffix 之前的 token 隐状态本来就不会注意后面的 suffix。changed-hunk pooling 排除尾部位置，因此后缀稳定性的一部分是计算结构可预期的。更有判别力的是 matched-token prefix / mid-context / suffix 位置对照、相同可见性和同样的任务证据，而不是继续堆相似的无关尾注。

**5. 统计与输入验证存在能被测试遗漏的边界**

`marginal_conditioned_violation_baseline` 在混合 invariant 与 equivariant 行时先合并 A-rate，再按关系类型占比混合。若两类的边际分布不同，它不是条件于各变换类型的独立基线。本次最小反例：invariant 类型恒为 A→A，equivariant 类型恒为 A→B；每类型的条件独立基线 violation 都为 0，当前聚合函数却给出 0.5。

在真实修复审计集上，按关系分别计算再平均，基线由 0.5000 变为 baseline 0.493956、repaired 0.493547。这里只证明基线定义影响数值，不把这次事后改算当作新门槛，也不声称所有单一变换表受影响。下一版应锁定按变换、必要时按来源分层的 null，并在每个 bootstrap 中同时重算 null 与 observed，直接对二者差值给置信区间。

pair-cluster bootstrap 已经比把所有 rendering 当独立样本更好，但不能消除同一项目、CVE、commit 或近重复函数间的依赖。已有 `check_primevul_pair_overlap.py` 支持字段和精确文本检查；仍需将这些证据绑定到本论文的确切多来源 train/discovery/confirmation/test 数据链，不能仅用不同 dataset 名称或 pair ID 宣称不存在泄漏。本次没有完成全量跨来源近重复审计，因此不作“已发现训练测试泄漏”的判断。

输入验证方面，`join_predictions` 对重复 ID 静默保留最后一条；修复评估会跳过缺失预测，且按裸 pair_key 而非 dataset::pair_key 聚合。当前两份修复预测经检查均无重复、缺失或额外 ID，所以这些是可靠性风险，不是本次已经发生的数据污染。应统一为严格验证与覆盖率报告。

不显著也不等于失败机制已证实：CrossVul +0.0086、p=0.508 应写“未验证可迁移增益”；两项 nuisance 点估计为负提示异质性，但若没有足够区间证据，不宜写成“证明训练效应不存在”。同理，180 对下未通过 -2pp 非劣界并不证明模型有害。应根据配对不一致比例和希望排除的效应量做设计分析，而不是事后加种子直到显著。

**6. 外部效度和人类证据仍不足**

Qwen 与 CodeBERT 的行为排序复现值得保留，但二者同时改变架构、预训练、分词器等因素，不能做架构本身的因果归因。额外 distilgpt2 和 0.5B generative judge 的 canonical accuracy 分别约 55.83% 和 46.67%，只能提供能力有限条件下的压力证据，不能替代对合格强模型的复现。

CrossVul 的简单净极性启发式 accuracy 达 0.855，模型与之有较高一致率；外部数据源可以携带更强的同类相关性，所以“换数据集还高分”不足以说明跨域漏洞语义迁移。闭世界 router 的约 0.73pp 行级增益也是另一类工程贡献，不宜作为本文关系理解的主证明。

人工标注并非完全没有：dashboard 记录 20 条 reviewer-confirmed evidence labels。但这是项目作者确认的选定队列，不能代替协议要求的 150 对、两名独立盲标、第三方或共识裁决。其选样集中于高价值冲突，不能估计全数据的标签错误率。round-3 AI pilot 也不能进入 human-gold 主结论。

当前数据构造强制每对恰好一个 vulnerable、一个 secure。真实审查还有两侧都安全、两侧都有问题、修复不完整、只修了一种漏洞以及上下文不足。这是任务选择带来的外推限制，应单列诊断集并保持现有二选一主任务的定义，不要悄悄改变历史指标。

**8. 建议的研究方向：先区分“候选绑定失败”与“漏洞语义失败”**

最值得追问的问题是：给定能够清晰识别的两个代码候选，模型究竟是不懂哪段代码更危险，还是不能把已有判断正确映射到候选名称和呈现方向？这两个解释需要不同修复，现有结果还没有充分区分。

我建议先做小规模、无训练、预先冻结的判别实验，而不是直接进入新架构。下述为未来设计建议，本次未运行任何新推理。

| 条件 | 保持与改变 | 判别作用 |
| --- | --- | --- |
| 候选绑定正对照 | 同一呈现结构，问题改为“哪侧含指定的唯一函数调用/字面量” | 若这里也失败，优先定位名称映射、输出头或格式读取问题 |
| 完整候选 vs 合法正反 diff | 固定候选代码及身份，明确写出源侧/目标侧，逐行验证映射 | 区分代码判断能力与 diff 解释能力；全量与长度匹配子集分别报告 |
| 呈现不变对照 | 换标签、换合法方向、改变无关文字位置；gold 按身份映射 | 测量应有的不变/等变，并控制 token 可见性 |
| 安全语义改变对照 | 小型可执行样例中改变真正相关的边界检查、操作符或调用，尽可能匹配长度及改动统计 | 排除“总选更短代码”等虽然一致但不懂漏洞的策略 |

不要为了完全独立操纵 `+/-` 而生成语义矛盾的 diff；无法在合法格式里分离的因素，就明确把它命名为联合干预。对于人工小型样例，用程序解析、功能测试与安全测试辅助确认；测试通过仍只覆盖给定测试范围。

在独立 development 集确认模型能完成绑定正对照并有基本任务能力，再冻结一个模型与一个真正不同系列的对照，进入未见项目/commit 的小型确认集。不要根据最终测试表现反复替换“合格模型”。每条样本的全部 rendering 作为一个 cluster，预先指定主指标、预算和停止规则。

有三种值得接受的结果：绑定控制都失败，则论文应偏向任务接口/绑定测量；绑定通过但安全语义改变不敏感，则证据指向语义不足；两者都通过、只在特定合法呈现失败，则更接近可定位的表示结构问题。三种结果都能推进理解，不需要任何一种必须产生“方法胜出”。

**9. 只有前面的判别结果支持，才进入方法研究**

方法研究的主比较应该是：相同 backbone、相同可见输入、相近训练和推理预算下，独立候选打分 `f(A)-f(B)`、冻结模型的结构投影、真正联合候选建模，以及一个根据诊断选择的训练干预。

主结果用“新的项目上，对所有有效呈现均正确的比例”和安全语义改变对照；同步报告 canonical 非劣、拒答覆盖率和错误接受率。结构保证放在单独列，不将零 violation 当作学习式创新。推理投影使用两次或更多前向计算，需要报告相应成本。只有联合模型在安全语义对照和外部确认集上优于投影及独立打分，才有理由说跨候选交互带来新的信息。

人类证据工作可并行推进：先以约 30–50 对检验标注协议的可执行性，再按实际分歧率和目标精度决定是否扩展到原计划的 150 对。模型/AI 建议在首次独立标注前隐藏。报告协议规定的 agreement、kappa、上下文充分性与分歧类型。不能由 LLM 代填成独立人工标签。

如果方法增益仍不稳定，就保留为有边界的负结果，不自动改损失、加 epoch 或扩大模型。相比再得到一个小的平均提升，明确哪种条件决定增益消失，更有研究价值。

**10. 实际执行优先级**

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P0：立即 | 修复 split-view 可见性、混合 null、严格输入验证；追踪 manifest mismatch | 实际变换行能追溯到候选源行；无效输入 fail closed；所有受影响分母/表格明确重算或标记待定 |
| P0：立即 | 对齐论文、协议和报告 | 600 对明确为三来源混合；raw/projection 分开；删去独立性和极性保证的过强表述；记录协议偏离 |
| P1：下一阶段 | 冻结小型绑定/语义判别协议并落实独立人工证据 | 能说明每个对照排除了哪个解释；数据、模型选择、统计方案、预算在确认前固定 |
| P1：收敛论文 | 一条主线、一套重算表、一套可复现输入与脚本 | 每个主声明都能从明确输入复算，且限制与正文一致 |
| P2：有证据再做 | 独立来源上的方法比较 | 学习增益超出冻结结构投影，并通过语义对照与预设 transfer/non-inferiority 门槛 |

不建议现在继续扩大 router、修改安全翻转阈值、堆同类 suffix、做大规模超参网格，或优先做 activation probing。前几项离核心问题更远，最后一项在行为判别与输入有效性未闭合时容易解释错对象。

文献定位也需要收窄：PrimeVul 已系统讨论数据质量、去重和真实评估；“已有 benchmark 高分不可靠”不足以成为独有创新。近期还有直接研究漏洞检测认知启发式与干扰的工作，因此新意应落在合法的候选身份变换、测量有效性、绑定与语义的区分，以及结构修复与学习增益的严格分解，而不是宽泛声称首次发现 shortcut。此次仅作定向原始来源核对，未做系统文献综述。[PrimeVul 原论文](https://arxiv.org/abs/2403.18624)，[Words Speak Louder Than Code 作者代码仓库](https://github.com/purseclab/cognitive-heuristics-vuln-detect)。
