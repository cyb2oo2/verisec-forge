# Prose Control on CrossVul `split_view` (v3)

Generated by `scripts/evaluate_split_view_prose_control.py`.
Artifact: `reports/split_view_prose_control_crossvul_v3.json`.

This closes the last open measurement in the Arc 2 rebuild: whether the
glyph-channel binding observed on PrimeVul / PatchEval / DeltaSecommits also
holds on CrossVul, an external source neither checkpoint was trained on.

All previous artifacts are unchanged. New artifacts carry the `_v3` suffix.

## Setup

CrossVul had no materialized nuisance families, so they were built from the
invariant-enforced eligible pool.

| Item | Value |
| --- | ---: |
| Pairs | 350 |
| Pair set identical to the CrossVul polarity audit | **350 / 350** |
| `split_view` rows | 700 (350 canonical + 350 side-swap) |
| Runtime `transformation_introduced_critical_truncation_rows` | 0 |
| Inference | both checkpoints, batch 4, length 1024 |

`split_view` regroups the identical content into `Removed from Side A (absent in
Side B)` / `Added in Side B (absent in Side A)` / `Unchanged context` blocks. No
`+`/`-` glyphs survive: the glyph control has **zero coverage on 99.71%** of
rows, so it decides by coin flip.

The **prose control** applies the identical semantics-free rule — net
added-minus-removed characters, sign `+1`, threshold `0` — but reads the
natural-language block headers instead of glyphs.

## The information is fully preserved

The decisive comparison is the first two rows. On the same 350 pairs:

- glyph control reading the **canonical unified diff**: `0.8057` canonical,
  `0.9800` equivariance, `0.7943` both-correct.
- prose control reading the **`split_view`** rendering: `0.8029`, `0.9829`,
  `0.8000`.

These are the same numbers. `split_view` does not ablate polarity — it re-encodes
it, losslessly, and a character-counting rule recovers it just as well from
English as from glyphs.

## The model does not merely degrade — its decision freezes

On the same 350 pairs, the baseline classifier scores `0.7429` canonical and
`0.7514` equivariance on the ordinary unified diff
([CrossVul v3 report](VERIPATCH_RR_STRUCTURAL_CONTROL_CROSSVUL_V3.md)). Under
`split_view`:

| Metric | canonical rendering | `split_view` |
| --- | ---: | ---: |
| canonical accuracy | `0.7429` | `0.4886` |
| side-swap equivariance | `0.7514` | **`0.0514`** |
| both-directions-correct | `0.6114` | `0.0343` |

Accuracy falls to chance, but the equivariance number is the more informative
one. At `0.0514` the model returns the **same answer** on the canonical and
swapped renderings for 94.9% of pairs. It is not answering noisily — it has
stopped responding to the side swap at all. Both-directions-correct collapses to
`0.0343` as a direct consequence: a frozen answer can be right in at most one of
the two directions.

The antisymmetric projection cannot rescue this. Built from frozen scores it
reaches only `0.5486`, barely above chance, versus `0.7714` on the ordinary
rendering of the same pairs.

## Verdict: the glyph-channel binding replicates on CrossVul, more strongly

| Source | prose control (`split_view`) | model (`split_view`) |
| --- | ---: | ---: |
| PrimeVul / PatchEval / DeltaSecommits pooled | `0.8433` | `0.5133` |
| **CrossVul** | `0.8029` | `0.4886` |

The finding holds on an external, zero-shot source: the polarity information
survives the transformation intact and is recoverable at `0.80` by a rule with no
model, while both checkpoints fall to chance. CrossVul additionally shows the
sharper form of the effect — equivariance collapsing to `0.0514` — which was not
visible in the pooled three-source measurement.

This supports the mechanism statement in `docs/ARC2_REVISED_MAIN_LINE.md`: the
classifier's competence is bound to the `+`/`-` glyph channel, and the identical
patch relation stated in prose is unusable to it. It is not a polarity ablation.

## Claim boundary

One control rule, one fitted threshold, 350 CrossVul pairs, two checkpoints, one
length (1024), one seed, one transform family. Behavioral and correlational: this
does not identify an internal mechanism, and `split_view` changes both the glyph
encoding and the block layout, so "glyph channel" names the input channel the
decision depends on, not a specific learned feature.
